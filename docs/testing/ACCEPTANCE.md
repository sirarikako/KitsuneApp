# KitsuneApp 跨模块验收矩阵

## 13. 验收与测试计划

### 13.1 用餐

- 点上一周和下一周时选中同一星期几，三餐列表、日期选择器和录入日期同步。覆盖连续切周及跨月后用日期选择器跳转。

- 新记录未选择在家吃不能保存；选是但未选方式不能保存；选否且方式为空可保存。
- 选否时仍可选择下厨／外卖或自定义方式；是改否保留内容。
- 下厨显示多选制作分类，外卖默认不显示；新增方式开关按设置生效，改名不影响引用。
- 新分类保存后可再次下拉选择，取消不创建；同日同餐冲突不能覆盖。
- 关闭全局开关后历史分类仍可查看，修改备注不丢失历史分类；主动切换到不支持分类的方式后按规则清除。
- 新增和编辑记录时，菜品内容与备注各占一行，长文本可横向滚动。包含中文、引号或换行的已有内容在编辑并保存其他字段后完整保留。
- 月度方式分布和分类计数正确，未填方式独立统计。

### 13.2 记账

- 验证四种流水的时间必填、默认当前分钟、补录和编辑保留、00:00／23:59 边界及非法时间拦截；同日排序正确，设备时区变化后业务日期时间不漂移，跨日与跨月统计按填写日期归属。
- JSON／CSV 往返保持时间，缺失或非法 time 报错；相同 ID 但业务时间不同视为冲突。

- 在含多条记录的流水页向上滚动，确认标题及筛选逐步收起、标签留在顶部、悬浮按钮收为圆形。停在列表中段反向滚动即可重新展开筛选；滚至顶部恢复扩展按钮，滚至底部最后一条可完整查看。切换钱包、统计时检查悬浮按钮隐藏；重新进入流水确认标题和按钮默认展开。
- 在窄屏和大字体下核对按月同行、自定义日期独占一行、长钱包名可读且按钮互不遮挡。
- 点金额和计算表达式时确认系统键盘不会打开，备注仍可输入。填入金额和备注，打开计算器输入部分表达式并重建 Activity，验证草稿恢复且取消保留先前金额。编辑和跨币种转账分别核对预填及回填结果。
- 计算器验证运算优先级、除零、非法表达式、非正数及单笔金额超界。验证 `1÷3×100` 在两位小数钱包中得到 `33.33`，JPY 按整数舍入。
- 覆盖 JPY 整数精度、两位及其他支持币种精度；货币间不混合加总。
- 同币种转账、跨币种双金额、整体编辑删除正确影响两侧余额，不计收支。
- 多次部分退款、超额退款拦截、退款删除、原支出修改约束及跨月净支出统计正确。以 A 支出 100、B 同币种退款到账 30 验证钱包范围内的 100、−30、70 及原支出分类归属。
- 流水与统计顶部使用同一日期范围控件，覆盖上／下月、弹窗内直接选年月、切回上次所选月份及草稿取消。应用跨月范围后两页均显示同一起止日期，流水、摘要和统计包含日期两端。缺少日期或起止颠倒时禁用应用，模式切换保留本次草稿。
- 收入和净支出分类显示精确金额、币种和横向比例条。覆盖退款导致的负净额、零金额及多币种。条长按同币种、同组金额绝对值计算，负金额仍带负号。
- 钱包初始余额、负余额、归档和已有流水后的币种限制正确。覆盖删除抵消支出后余额超过 64 位上限，仍可保存并精确显示结果。
- 验证独立核算开关默认关闭、可在有流水时切换，并保留至 JSON 备份／恢复；首页、账本流水、收支统计及分类排行默认只含常规钱包；手动选中独立核算钱包和“全部钱包（含独立核算）”时结果正确，恢复默认后重新排除。归档、空常规钱包、跨币种、跨常规／独立钱包转账及跨钱包退款均不丢流水或误改余额；手动选择在标签切换和钱包属性变化后按规则保留。
- 流水和统计都打开居中的钱包范围弹窗。只有手动模式显示钱包勾选项；从常规或全部切入手选时初始排除独立核算钱包。验证模式切换、空手选禁用应用、取消、恢复默认、窄屏和长钱包列表。
- 记一笔及快捷记账不自动预选独立核算钱包；最近使用的是独立钱包时回退到常规钱包，无常规钱包时留空并允许手选。钱包列表所有钱包均可查看余额，独立核算标识清晰。
- 窄屏钱包卡片上核对金额可读性、独立核算和归档标识、右上角编辑及余额下方的文字分类入口，验证两个操作打开对应钱包。
- 验证设置中可分别管理通用收入／支出类别及指定钱包的专属收入／支出类别；DEFAULT 使用最新通用分类，CUSTOM 只使用该钱包的分类加全局“未分类”，即使列表为空也不能意外回退。两个方向切换互不影响，独立核算开关互不影响；关闭 CUSTOM 保留旧类别、历史引用及跨钱包退款分类。
- 核对分类列表中的名称、停用状态和固定兜底项。点分类行进入详情，验证改名、排序、启停和取消草稿。钱包使用通用分类时预览为只读，仍可管理已保存的专属分类。
- 验证切换钱包、收支类型时清空不兼容的待选分类而不按名称自动匹配；现有记录只改备注不丢失停用或非当前模式分类；相同名称不同钱包分类 ID 不混合统计。CSV 按钱包、类别归属解析（不因同名误映射），JSON 完整恢复归属、模式及历史数据，缺少新字段的旧数据按默认模式兼容。

### 13.3 外观与图标

- 三种明暗模式与三种配色来源组合正确；旧系统动态取色选项与恢复回退正确。
- 保存非默认配色后冷启动，检查浅色和深色下的启动窗口、读取中画面及第一帧首页；首页直接采用已保存的外观。数据库打开失败时仍可按原流程重试或建立独立新库。
- 五套预设在浅色和深色下均以各自的色调区分背景与卡片。核对首页、用餐、账本、设置和外观草稿，比较 HTML 与 Android 的色阶及文字对比度。
- 跟随系统壁纸时，核对浅色和深色下页面背景与卡片分块有独立层次，草稿预览与应用后的界面一致；切换系统配色后继续核对文字对比度。
- 自选 HEX 校验、独立浅色／深色预览、应用、取消、恢复默认、重启与 JSON 恢复正确。切换预览或编辑明暗草稿不影响其他页面；取消后保留此前应用的明暗与配色。
- 打开设置时预览区隐藏。修改明暗、配色来源、预设或自选主色后显示；取消、成功应用或把草稿改回已应用值后隐藏。无效 HEX 阻止应用，预览区保持可见以便修正或取消。
- 首页同时展示 CAD、CNY、JPY 等币种时，CNY 排在首位，其余币种保留相对顺序。钱包范围没有 CNY 时，只展示已有币种。收支卡片底部的全宽“记一笔”及标题行的“查看账本”都可操作。
- 在 320 dp、放大字体、浅色、深色、自选色及系统动态色下，核对首页两张卡片的宽度、内边距、间距和主按钮。覆盖无常规钱包、单币种零金额、多币种、大额和负净支出。
- 切换用餐和账本时，核对页标题、筛选、列表、表单和统计使用[共用界面规范](../features/01-common.md#31-用餐与账本的共用界面)的样式；检查统一视觉在不同配色、浅色、深色及窄屏下的布局，验证长菜品、长备注、长钱包名和大额金额的展示。
- 按[全局动效规范](../features/01-common.md#32-全局动效与页面过渡)逐项验收四页导航、子页双向滑动、记录容器展开／回退及无源卡片回退、底部弹层、确认弹窗、页内更新、外观预览展开／收起与全局颜色过渡；所有配色、浅色／深色统一时长及缓动。覆盖快速连续导航、返回中断、当前页重复点击、慢加载、键盘与焦点、窗口尺寸变化及系统关闭／减少动画；不得出现白屏、错误页面、重复路由、操作阻塞、表单草稿丢失或正文不可读。实机记录过渡时长及流畅性，核对底栏和状态栏位置、月度控件与内容的动画范围。
- 从设置依次进入「用餐方式」「下厨」，验证编辑页从右侧滑入。分别使用页面返回键和系统返回，验证编辑页向右滑出、用餐方式列表从左侧滑回。
- 拖动不备份，系统变色不备份，一次实际应用只生成一次修订。
- 检查所有页面、弹窗、表单、图表、计算器、系统栏、大字体和键盘布局；验证关键文字对比度。
- 在用餐和账本中核对主题日期与时间弹窗的明暗配色。点日历顶部年月，验证无效年份禁用月份，以及直接跳到其他年份的月份后能选择闰日。用左右箭头或滑动切月，验证浏览不改变所选日期。验证窄屏日期输入、24 小时时钟与手动输入，非法日期或时间不能确认，取消保留原值。
- 验证流水、账目详情和外观示例的支出金额使用同一语义色，区别于收入和错误。检查预设、自选极端色和系统壁纸配色在浅色、深色下的支出文字对比度至少为 4.5:1。
- 狐狸图标在圆形／圆角方形遮罩及小尺寸下不裁掉耳朵或五官；彩色和单色主题图标都可辨认。

### 13.4 备份、导入与恢复

- 验证已连接的 GitHub 备份页先显示当前同步状态和上次成功时间，可同步时提供实色“立即备份”。远端核对与恢复另成一组，取消恢复或覆盖确认时保留原数据。
- 目录不可用或断网时连续提交 A、B、C，保存均成功且每个目标的待处理状态合并到 C。恢复访问后能从备份恢复 C 的完整数据，包含期间的新增、修改和删除。
- 在 A 执行期间保存 B、C，验证 A 的完成只确认 A，最终两个已启用目标都能备份 C。验证数据库提交后、后台任务调度前进程退出，重启可补调度。
- 覆盖写入、校验、发布和清理各阶段中断。只有发布成功的文件可用于自动恢复，新文件发布前上一份仍可恢复，清理成功后目录中只剩本数据集最新一份 AUTO。验证不支持原子重命名的目录及手动导出、恢复前备份和其他数据集文件的保护。
- 验证同秒生成文件、设备时钟回拨和换机后复用旧目录。命名碰撞时已有文件仍可恢复，新备份发布成功后保留该份。
- 分别外部删除最新文件夹备份的 JSON 或完成标记，保持本机修订不变并点击“立即备份”。验证重新生成、更新上次成功时间，并能从新文件打开恢复预览。验证同秒重建时不会复用残留标记的序号。
- 按[格式验收](../data/04-compatibility.md)核对所有完整备份的 UTC+8 时间、保存建议名称、恢复摘要和旧 UTC 备份兼容。
- 覆盖断网、目录失效、授权撤销、外部空间不足、进程退出和重启补任务；状态不得误报成功。
- 验证编辑含中文、换行和转义字符的字段，达到结构上限可保存，超过上限则指出具体字段。并发提交、批量导入、编辑关联与删除后核对累计数。验证达到 80% 时出现对应提醒，只有云端超限时录入和本地备份可继续，GitHub 明确显示当前修订失败及上次成功时间，后续缩小快照可恢复上传。
- 验证首笔变更后 1 分钟合并、后续变更不推迟窗口、后台写入间隔至少 30 分钟、空闲无提交和断网恢复只上传最新修订。验证保存恰好发生在 Worker 退出时也会安排后继，进程重启可补调度，恢复或切换目标后的旧任务不能写入。验证“立即备份”只跳过普通频率限制。
- 验证系统时钟前拨、回拨、进程重启和设备重启时，合并窗口、间隔与退避符合计时规则。仅 Wi-Fi 模式覆盖计费 Wi-Fi、非计费移动网络、VPN 承载不明和写入中切网。
- 验证 1 MiB 下载方式切换及 32 MiB 应用上限，覆盖大文件 `raw` 下载、元数据与下载之间更新分支、字节数或 blob SHA 不符、流式 Base64 上传，以及从本地 JSON 恢复较早提交中的快照或超过云端应用上限的有效文件。低内存真机记录大文件导出和恢复的峰值堆占用，确认没有整份文件级内存分配。超限、结构校验失败及空间不足时保留本机与原有云端备份。
- 验证自动备份成功后才检查仓库容量。默认 800 MB 时，`size` 等于 800,000 KB 不提示，高于该值才提示。覆盖无效阈值不覆盖原设置、改值后立即重判、后台完成后下次打开 App 提示、关闭后重启去重、再增长达到阈值的 10% 及回落后的重新提示。查询失败、限流或目标切换不得误报容量或变更已成功的备份状态。
- 在生成、下载、解析、上传前与请求可能已发出时分别模拟应用超时、系统停止或进程终止。验证未完成工作不记成功、旧修订仍可核对、后继优先核对不明写入并在可重试时重新生成最新完整快照。覆盖远端已接收、仍是原版本和第三方修改，以及临时文件与暂存库的回收。
- 验证「立即备份」经版本核对后提交，任务提交与确认发布分开显示。普通 GitHub 恢复有摘要、保护说明和独立确认；缺失时只能返回。
- 验证冲突处理的取消、恢复和二次确认覆盖；删除后显示重建。核对后改变远端 SHA、仓库或本机数据集，旧预览不能授权写入或恢复。
- 验证 Wi-Fi 快速连续切换、配置保存失败回滚、表单草稿及 Activity 重建。切换时保留控件位置、滚动和独立操作，不显示页面进度。
- 分别验证等待 Wi-Fi、等待上传间隔、临时失败退避、上传中和人工暂停。验证前后台首次提醒、稍后处理、Activity 重建及进程重启后的去重，以及问题解决后设置页警告消失和再次暂停时的新提醒。
- 按 GitHub API 错误表逐项验证，重点检查权限错误不会被判定为文件缺失、限流未到期不能重试、`409` 和疑似并发创建的 `422` 不会覆盖远端较新版本。
- 两台设备依同一 SHA 并发上传，后写入者须暂停。覆盖首次绑定同时创建、首次已有文件、文件被删除、其他数据集替换、更换分支、Token 失效和确认后远端再次变化。验证取消保留待上传修订，重建需确认，分支的无关提交不阻塞备份。
- 覆盖上传响应丢失时远端已发布、仍是原基准和已被其他设备替换的情况。覆盖恢复期间旧任务尚未发出或已发出请求，以及本机离线恢复后补核对；旧结果不能解除暂停或确认新代次的修订。
- 在全新安装中恢复完整 JSON，用餐、方式配置、分类、钱包余额、退款／转账关系、归档状态和主题一致。
- 检查合并后的 manifest 和两版 XML，并覆盖旧版 Auto Backup、新版云备份及设备直传。模拟仅复制 Room、仅复制连接／任务状态、安装标识缺失或不符、同代次本机修订倒退，验证未归属旧库不会静默变为活动库，旧任务不能使用旧 Token 或发布。重启后仍须重新配置并确认当前目标，覆盖有文件和缺失文件两种情形。同一安装正常重启和版本更新可按原状态继续。
- 覆盖全新安装直接恢复、有数据但无授权目录的单次保护导出及导出取消或失败。已绑定 GitHub 时，恢复后继续录入、重启或手动发起备份均须保持远端文件，直到用户另行确认用本机数据更新云端。
- 在完整恢复进行时旋转屏幕或重建 Activity，验证任务继续使用同一暂存库。验证成功只提交一次并回收暂存文件，失败保留本机数据和待重试的预览，取消预览后回收暂存文件。
- 损坏或较新格式、无效引用、无效金额、日期餐次冲突及失败恢复都不能破坏现有数据。
- CSV 覆盖中文、引号、逗号、多行文本、制作分类数组、重复 ID、重复文件、同批退款引用、精度错误和整批回滚。
- 凭证不出现在导出文件、仓库或日志中；备份任务变化不会递归触发新备份。

### 13.5 测试实施与交付证据
