# KitsuneApp UI 设计稿

更新日期：2026-11-21（Asia/Shanghai）。此处保存网页设计稿，供后续 Android 开发对照。

正式设计仅保留原杏橙手账的统一组件造型，默认杏橙配色。茶绿、雾蓝、薰衣草、豆沙粉及自选主色、系统壁纸取色继续保留，所有配色使用同一布局与形状规范；无独立视觉方案切换。业务、设计规则继续集中维护在 [PLAN.md](../PLAN.md)，数据契约以 [DATA_FORMAT.md](../DATA_FORMAT.md) 为准；本目录提供可查看、可编辑的视觉依据。

## 查看与维护

直接用现代 Edge 或 Chrome 打开 [index.html](index.html)，可离线查看，无需启动服务或安装 Android 工具链。预览仅显示唯一设计，手机界面内可切换首页、用餐、记账、设置；在设置中修改配色和明暗。

修改源片段后重新生成预览；命令和已验证的工具版本统一记录在[项目 README](../../README.md#ui-设计预览)。不要只修改生成的 index.html，否则下次打包会覆盖修改。此前的 18 张过期截图已从工作树删除。现行视觉以本目录源稿及同版本生成的 [index.html](index.html) 为准，不使用旧截图。后续如增补截图，须从通过视觉验收的当前预览生成并记录对应的源稿 SHA-256，更新设计时同步更新或删除过期截图。

原始片段保留对话中的可选设计调参接口；普通浏览器没有该侧栏，可通过应用内设置预览调色板与明暗。独立导出将长文本的悬停提示转换为浏览器原生提示，避免依赖在线定位库；点击记录始终可查看完整内容。

## 视觉与页面索引

当前源稿的手机画布最大宽度为 390 CSS px。卡片圆角统一为 17 px，不随调色板变化。用餐的按日记录、筛选结果和账本流水共用同一记录行，基准高度为 70 CSS px，随内容增高。筛选控件、录入表单和统计面板也共用样式，见 [PLAN 第 3.1 节](../PLAN.md#31-用餐与账本的共用界面)。Android 实现需转为合适的 dp／sp，并适配字体缩放和屏幕宽度。

当前通用容器采用「主题卡片底色 + 1px 描边」：首页收支与三餐进度、用餐和账本记录、统计、设置分组及外观预览一致；普通输入、筛选、次要操作与计算器数字键也使用细描边。仅主要动作、选中态、危险确认和有意义的标识／图表保留实色强调。所有配色共用圆角、描边与组件形状，不再存在独立备选造型。

共用控件、间距、文字层级、图标和弹窗采用 PLAN 3.1 的尺寸规范。外观预览复用实际记录、标签与主要按钮的样式，独立生成完整主题角色；网页颜色生成按 WCAG 相对亮度对文字、选中、主操作及危险操作进行对比度调整，目标至少 4.5:1。

颜色和组件的实现以 PLAN 的 Material 3 主题规则为准。网页使用带文字对比度保护的近似颜色混合，尚未采用 Android Material Color Utilities 的完整 Tonal Spot 色阶。

页面通过交互预览查看；当前不保留静态 UI 截图。

## 全局动效设计

页面过渡、弹层、记录详情、局部内容更新和外观变更统一遵循 [PLAN 第 3.2 节](../PLAN.md#32-全局动效与页面过渡)。四个底部入口采用 Fade Through；层级导航、记录容器变形及临时弹层按场景区分。同一套规则适用于全部配色及明暗模式，不改变现有页面布局及业务入口。

网页源稿和离线预览现已加入四页淡入淡出、子页双向滑动、可见记录来源的容器裁剪展开／收回（不满足条件时水平过渡）、计算器和钱包底部弹层、删除确认、日期／页内标签／筛选结果淡入淡出以及外观预览区高度过渡。应用主题时同明暗模式下插值颜色角色，跨明暗直接同步替换前景／背景以避免低对比度中间帧。网页使用 Web Animations API，遵循 prefers-reduced-motion；Android 正式实现仍以 PLAN 为准。

演示没有登录功能，也不会连接 GitHub 或读写个人数据。演示记录、钱包余额及所有金额均为虚构样例；刷新后业务记录重新初始化，部分界面偏好可能由浏览器本地存储保留。

“跟随系统壁纸”在网页中使用固定示意色板，正式应用将使用 Android 12 及以上系统提供的 Material 动态颜色。设置里有未应用的外观修改时才显示预览、“取消”和“应用外观”。应用成功、取消或改回已应用值后收起预览区。“预览明暗”只切换示例区域。切换来源保留上次预设／自选色。具体规则见 [PLAN 第 6 节](../PLAN.md#6-外观调色板与系统主题)。

日期、分类、钱包、ID 与金额的演示结构不是正式 JSON／CSV 数据格式。正式开发需按 DATA_FORMAT 建模，按 PLAN 完成转账原子性、退款保护、金额范围和精度、备份、分类生命周期等全部规则，不能把网页的演示限额、固定选项或简单数组当作完整实现。

## 实际验证

本轮删除备选视觉原型及切换入口，仅保留单一手机预览。静态检查 JavaScript 语法通过；逐一比较 222 个种子色在常规／系统示意取色和明暗下的完整颜色角色，保留方案的颜色结果与原实现完全一致。重新打包离线 HTML 并更新校验清单；尚未执行当前版本浏览器视觉回归。

本轮动效更新检查了源稿 JavaScript 语法、原预览和源稿哈希，按原打包规则替换独立预览中转义的源片段并重算 SHA-256；保留模板与图标字节不变。尚未进行浏览器实际渲染、快速连续点击与配色／明暗／窄屏回归，Android 动效亦未实现。不能将静态检查视为实测通过。

本轮资料清理移除 18 张旧截图、191 条被覆盖的 CSS 声明（涉及 77 条规则）及 8 条未使用的样式规则。业务 JavaScript 与页面标记保持不变；重新生成独立预览与校验清单，尚未执行浏览器视觉回归。

此前全局组件统一（历史验证，含已废弃的备选视觉）：以纯函数计算检查 222 个种子色（含五种预设、动态色板示意、黑白及饱和 RGB 网格）、两套主题、常规和系统示意配色、两种明暗，共 39072 组前景／背景对比；最低 4.60:1。该检查是颜色公式验证，不是浏览器渲染测试。交互预览重新打包；最新版本尚未执行浏览器视觉回归，旧截图已删除。

### 历史验证（全局组件统一之前，不代表当前版本已验收）

2026-11-21 在离线 Chromium 中验证了两套方案的浅色和深色界面，覆盖 320 CSS px 窄屏视口与约 390 CSS px 标准手机画布。核对两模块的记录行、图标和保存按钮样式，并走查用餐录入、必填检查、筛选、统计与删除取消，以及账本的日期范围、钱包选择器、计算器回填、保存和删除。

同日走查两套方案在上述尺寸和明暗组合下的设置页。验证默认隐藏、编辑后展开、取消／应用／手动改回后收起、无效 HEX 拦截，以及应用后切换页面保持新外观。

2026-11-18 使用无头 Chromium 以离线模式加载仓库的独立预览文件，在 320／390 CSS px 手机画布上检查了以下场景。

- 当时的首页原型均展示 CNY 与 JPY。跨月日期在流水和统计间保持一致，包含起止日。测试了无效日期、取消、返回按月及跨钱包退款的分类和金额。
- 独立明暗预览只影响示例区域。验证外观草稿取消后回到已应用状态，应用后跨页面生效。
- 计算器 `1÷3×100` 回填 `33.33`，拒绝除零与超界单笔金额。删除抵消支出后，钱包可精确显示超出 64 位的余额。
- 上述流程期间未发现 HTTP／HTTPS 请求和浏览器脚本错误。

2026-11-17 的离线预览验收另覆盖用餐录入与筛选、导航和删除确认流程。Android 编译、系统动态颜色、真机及数据集成验证在原生实现阶段执行。
