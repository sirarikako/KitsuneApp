# KitsuneApp UI 设计稿

更新日期：2026-11-21（Asia/Shanghai）。此处保存网页设计稿，供后续 Android 开发对照。

保留两套视觉：默认展示“杏橙手账”，“清爽日常”作为备选。两套方案使用相同的业务交互。业务、设计规则继续集中维护在 [PLAN.md](../PLAN.md)，数据契约以 [DATA_FORMAT.md](../DATA_FORMAT.md) 为准；本目录提供可查看、可编辑的视觉依据。

## 查看与维护

直接用现代 Edge 或 Chrome 打开 [index.html](index.html)，可离线查看，无需启动服务或安装 Android 工具链。预览底部可切换两套方案，手机界面内可切换首页、用餐、记账、设置。

| 文件 | 用途 |

| [index.html](index.html) | 独立预览，样式、交互和图标均已内嵌，可单独复制查看 |
| [kitsune-ui.fragment.html](kitsune-ui.fragment.html) | 可编辑界面与交互源稿 |

| [vendor/lucide-1.8.0.min.js](vendor/lucide-1.8.0.min.js) | 离线图标库；原始许可证见 [LUCIDE-LICENSE](vendor/LUCIDE-LICENSE) |
| [screenshots](screenshots/) | 18 张关键页面截图，含用餐与账本的共用界面及系统壁纸配色示意 |

修改源片段后重新生成预览；命令和已验证的工具版本统一记录在[项目 README](../../README.md#ui-设计预览)。不要只修改生成的 index.html，否则下次打包会覆盖修改。截图是设计快照，重新调整界面后也应更新对应截图。

原始片段保留对话中的可选设计调参接口；普通浏览器没有该侧栏，可通过应用内设置预览调色板与明暗。独立导出将长文本的悬停提示转换为浏览器原生提示，避免依赖在线定位库；点击记录始终可查看完整内容。

## 视觉与页面索引

当前源稿的手机画布最大宽度为 390 CSS px。“杏橙手账”的卡片圆角为 17 px，“清爽日常”为 13 px。用餐的按日记录、筛选结果和账本流水共用同一记录行，基准高度为 70 CSS px，随内容增高。筛选控件、录入表单和统计面板也共用样式，见 [PLAN 第 3.1 节](../PLAN.md#31-用餐与账本的共用界面)。Android 实现需转为合适的 dp／sp，并适配字体缩放和屏幕宽度。

颜色和组件的实现以 PLAN 的 Material 3 主题规则为准。网页使用了近似的颜色混合，尚未采用 Android Material Color Utilities 的完整 Tonal Spot 色阶。

## 与正式开发的边界

| 范围 | 当前状态 |
| --- | --- |
| 四页导航、首页多币种收支 | 已在网页演示，首页以固定样例月份展示 CNY 与 JPY |
| 用餐录入、编辑、删除确认、组合筛选、紧凑列表及统计条形 | 已在网页演示，数据只在当前页面内变化 |
| 流水与统计共享的日期范围、钱包筛选及跨钱包退款 | 已在网页演示自定义日期、返回按月和按到账钱包统计，退款来自固定样例 |
| 记一笔、计算器回填、账目详情和删除 | 已在网页演示，非正式财务运行时 |
| 预设／自选／系统壁纸配色与明暗 | 已在网页演示独立浅色／深色预览及外观草稿应用、取消。系统壁纸选项使用示意色板 |
| 分类管理、钱包管理、转账、新增退款、导入导出、备份与恢复 | 当前作为 Android 实现阶段交付，设置中多数条目仅展示布局 |
| 原创狐狸图标 | 已保留在 [artwork](../../artwork/README.md)；网页首页仍为 emoji 示意，新版接入与设备验收待完成 |
| Android／Room／WorkManager／APK | 尚未初始化或实现 |

演示没有登录功能，也不会连接 GitHub 或读写个人数据。演示记录、钱包余额及所有金额均为虚构样例；刷新后业务记录重新初始化，部分界面偏好可能由浏览器本地存储保留。

“跟随系统壁纸”在网页中使用固定示意色板，正式应用将使用 Android 12 及以上系统提供的 Material 动态颜色。设置里有未应用的外观修改时才显示预览、“取消”和“应用外观”。应用成功、取消或改回已应用值后收起预览区。“预览明暗”只切换示例区域。切换来源保留上次预设／自选色。具体规则见 [PLAN 第 6 节](../PLAN.md#6-外观调色板与系统主题)。

日期、分类、钱包、ID 与金额的演示结构不是正式 JSON／CSV 数据格式。正式开发需按 DATA_FORMAT 建模，按 PLAN 完成转账原子性、退款保护、金额范围和精度、备份、分类生命周期等全部规则，不能把网页的演示限额、固定选项或简单数组当作完整实现。

## 实际验证

2026-11-21 在离线 Chromium 中验证了两套方案的浅色和深色界面，覆盖 320 CSS px 窄屏视口与约 390 CSS px 标准手机画布。核对两模块的记录行、图标和保存按钮样式，并走查用餐录入、必填检查、筛选、统计与删除取消，以及账本的日期范围、钱包选择器、计算器回填、保存和删除。受影响的截图已刷新，并补充用餐编辑快照。

同日走查两套方案在上述尺寸和明暗组合下的设置页。验证默认隐藏、编辑后展开、取消／应用／手动改回后收起、无效 HEX 拦截，以及应用后切换页面保持新外观。设置页及展开预览截图已更新。

2026-11-18 使用无头 Chromium 以离线模式加载仓库的独立预览文件，在 320／390 CSS px 手机画布上检查了以下场景。

- 两套首页都展示 CNY 与 JPY。跨月日期在流水和统计间保持一致，包含起止日。测试了无效日期、取消、返回按月及跨钱包退款的分类和金额。
- 独立明暗预览只影响示例区域。验证外观草稿取消后回到已应用状态，应用后跨页面生效。
- 计算器 `1÷3×100` 回填 `33.33`，拒绝除零与超界单笔金额。删除抵消支出后，钱包可精确显示超出 64 位的余额。
- 受影响的 9 张首页、记账和外观截图由独立预览重新生成。上述流程期间未发现 HTTP／HTTPS 请求和浏览器脚本错误。

2026-11-17 的离线预览验收另覆盖用餐录入与筛选、旧版截图涉及的导航和删除确认流程。Android 编译、系统动态颜色、真机及数据集成验证在原生实现阶段执行。
